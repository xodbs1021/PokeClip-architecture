# ADR-016: 방송 생명주기 이벤트 전달 보증 — 이벤트 등급화 + 상태 재조정

- **상태**: 제안 (팀 리뷰 후 채택 — maxReceiveCount 등 구체 수치 확정 필요)
- **결정일**: 2026-07-23
- **관련**: [ADR-013](ADR-013_인프라.md) · [ADR-006](ADR-006_DB_PostgreSQL.md)
- **반영 산출물**: 5_CA · 10_데이터플로우 · 11_역할분담(인터페이스 계약)

## 컨텍스트

SQS는 4큐 + 각 큐 DLQ로 구성되고, 소비자가 `maxReceiveCount`를 초과해 실패하면 메시지가 DLQ로 격리된다(ADR-013). 그런데 Broadcast Event Q가 나르는 `broadcast.started`는 다른 메시지와 **유실 피해 규모가 질적으로 다르다** — 이 이벤트가 소비 실패로 DLQ에 격리되면 Chat Collector 수집·하이라이트 감지가 켜지지 않아 **해당 방송 전체가 클립 0**이 된다. `broadcast.ended`(마감·정리 지연) 및 일반 잡(개별 산출물 1건 지연)과는 피해 등급이 다르다.

기존 문서는 "4큐 + 각 DLQ"까지만 정하고 이벤트별 전달 보증 수준을 구분하지 않았다. 모든 메시지를 동일 정책(동일 `maxReceiveCount`·동일 알람 등급)으로 다루면 Critical 이벤트를 과소보호하게 된다.

## 결정

이벤트를 **중요도 등급으로 나누고, 등급별로 전달 보증 정책을 차등 적용**한다. 더불어 라이브 상태의 정본(source of truth)을 이벤트 메시지에서 분리해, 이벤트 유실이 "영구 손실"이 아니라 "복구 가능한 지연"이 되도록 만든다.

### 1. 이벤트 등급

| 등급 | 이벤트 | 유실 시 피해 |
|---|---|---|
| **Critical** | `broadcast.started` | 방송 전체 클립 0 |
| **High** | `broadcast.ended` | 마감·정리 지연(재조정으로 복구) |
| **Normal** | render · AI · upload 잡 | 개별 산출물 1건 지연 |

### 2. 등급별 정책 (수치는 팀 확정)

| 정책 | Critical | High | Normal |
|---|---|---|---|
| `maxReceiveCount` | 8~10 (넉넉) | 5 | 3 |
| DLQ 알람 | **1건=즉시 P1 호출** | P2 | 집계 후 조사 |
| 상태 재조정 | 적용 | 적용 | 미적용 |

### 3. 라이브 상태의 정본 분리 (불변식)

**라이브 여부의 source of truth는 이벤트 메시지가 아니라 `Redis Live Broadcast State` + 진행 중 SRT 연결이다.** `broadcast.started`는 그 상태를 세우는 트리거일 뿐, 유일 진실이 아니다. → 이벤트를 놓쳐도 다른 신호(세그먼트 유입·SRT 연결·Redis 상태)로 상태를 재구성할 수 있다.

### 4. 상태 재조정 (reconciliation)

Clip Service가 주기적으로 **"S3에 세그먼트가 유입 중인데 수집이 켜지지 않은 채널"**을 감지해 수집을 자동 기동한다. 이벤트 유실의 최종 안전망.

### 5. 멱등한 시작 핸들러

`broadcast.started` 처리는 멱등(이미 라이브면 no-op)이어서, DLQ redrive·재조정·중복 수신에도 중복 수집이 발생하지 않는다(역할분담 계약1 멱등성 원칙의 연장).

### 6. MVP vs Target Production

| 구성 | MVP (1달) | Target |
|---|---|---|
| 등급별 `maxReceiveCount` 차등 | ✅ | ✅ |
| Broadcast DLQ 즉시 알람 | ✅ | ✅ |
| 멱등 시작 핸들러 | ✅ | ✅ |
| 유실 복구 | **수동 redrive** | **자동 재조정 루프(4번)** |

→ MVP는 설정값(재시도·알람)과 멱등 핸들러만으로 치명적 유실을 막고, 자동 재조정은 Target으로 미뤄 1달 일정을 보존한다.

## 근거

- **피해 비대칭에 정책을 맞춘다** — 유실 피해가 질적으로 다른데 동일 정책을 쓰는 것은 비합리적. 등급화가 최소 비용으로 Critical을 보호한다.
- **단일 지점 의존 제거** — 라이브 상태를 이벤트 한 통에 의존시키지 않으면, 큐/소비자 장애가 방송 전체 손실로 번지지 않는다(불변식 3).
- **MVP 부담 최소** — MVP는 설정값(재시도·알람)과 멱등 핸들러만으로 치명적 유실을 막고, 무인 복구(자동 재조정)는 Target으로 미뤄 1달 수직 슬라이스 일정을 지킨다.

## 검토한 대안

- **모든 이벤트 동일 정책 유지**: 단순하나 Critical 과소보호. 기각.
- **Broadcast Event Q를 FIFO + exactly-once로 전환**: 중복은 줄지만 처리량↓이고, 전달 실패의 실제 원인(소비자 크래시)은 여전히 DLQ행 → 근본 해결 아님. 기각.
- **Broadcast 이벤트에 DLQ 미적용(무한 재시도)**: 독약 이벤트가 큐를 영구 점유해 전체 마비 위험. 기각.
- **이벤트 폐기 후 순수 폴링(Clip이 Redis/S3만 감시)**: 재조정과 동일 메커니즘이나 이벤트의 즉시성(수집 지연 최소화)을 포기. → **이벤트 주도 + 재조정 백업**의 혼합을 채택.
