# ADR-001: 송출 프로토콜 — SRT + MPEG-TS (본방과 동시 송출)

- **상태**: 채택
- **결정일**: 2026-07-20
- **관련**: [ADR-002](ADR-002_OBS플러그인.md) · [ADR-003](ADR-003_미디어서버_Go.md)
- **반영 산출물**: 3_SA · 4_SysA

## 컨텍스트

멀티오디오 6트랙을 담은 방송 영상을 본방(치지직/SOOP)과 병행으로 자체 서버에 보내야 한다. 멀티트랙을 온전히 실어 나를 수 있고, 가정용 회선의 손실·지터에 강한 전송 조합이 필요하다.

## 결정

자체 OBS 플러그인이 본방(치지직/SOOP RTMP)과 병행으로 SRT+MPEG-TS를 자체 서버에 송출한다. 본방 비디오 인코더를 공유해 추가 영상 인코딩 부하 0으로 만든다.

## 근거

- MPEG-TS는 멀티오디오 트랙이 네이티브(PID별 엘리멘터리 스트림) — 방송업계가 다국어 컨트리뷰션에 수십 년 쓴 표준. Clevercast가 OBS+SRT로 12개 언어(6트랙) 상용 운영 중이라 상용 검증도 끝난 조합.
- SRT는 ARQ 재전송·AES 암호화·RTT/손실 통계 API 제공. 통계는 대시보드 송출 상태 위젯의 데이터 소스가 된다.
- 동시 송출 부하 검증: 인코더 공유(obs-multi-rtmp와 동일 패턴) 시 추가 부하는 AAC 인코더 ~10개(한 자릿수 % CPU). 업로드 대역폭 합계 ~21Mbps로 국내 100Mbps 대칭 회선에서 여유. 치지직+SOOP 동시송출은 국내에서 이미 흔한 방송 형태.

## 검토한 대안

- **Enhanced RTMP v2**: 스펙상 멀티트랙 지원(trackId)이고 Twitch가 채택했으나, 수신 서버 생태계 미성숙(MediaMTX조차 미지원 이슈 상태) + TCP 기반이라 손실 네트워크에서 SRT 대비 불리 → 시기상조.
- **RIST**: SMPTE 2026 연구에서 악조건(무선)에선 SRT보다 우세하나 저손실 유선에선 동급. 생태계·툴링은 SRT 우위. 유선 홈 스튜디오 시나리오라 전환 이득 없음.
- **WHIP/WebRTC**: OBS 네이티브 지원이 있으나 1비디오+1오디오, Opus 강제 → 요구사항 미달로 즉시 탈락.
- **MoQ(Media over QUIC)**: IETF 표준화 진행 중, 프로덕션 미성숙 → 기술 선정으로는 도박.
