# ADR-008: 오디오 트랙 UX — 상시 VAD 제거

- **상태**: 채택
- **결정일**: 2026-07-20
- **관련**: [ADR-002](ADR-002_OBS플러그인.md) · [ADR-009](ADR-009_클립내보내기.md)
- **반영 산출물**: 1_IA · 3_SA

## 컨텍스트

오디오 6트랙 중 "사람 음성이 있는 트랙"을 자동으로 찾아줄 것인가. 상시 VAD(음성 활동 감지) 파이프라인의 서버 오버헤드 우려가 출발점이었고, 논의 중 "에디터에서 비어 있지 않은 트랙만 보여주고 직접 들어보게 하자"는 대안이 나왔다.

## 결정

음성 트랙 자동 분류(상시 VAD 파이프라인)를 스펙에서 제거. 대신 클립 에디터가 열릴 때 구간만 트랙별 디코드해 웨이브폼을 그리고, 그 부산물인 RMS로 무음 트랙을 숨긴다. 트랙 정렬·기본 선택은 소스 타입 메타데이터(마이크 디바이스/Discord.exe/게임 exe)로만. 사용자가 미리듣기(솔로)로 직접 선택 → 선택 트랙만 Whisper.

## 근거 — "사람이 있는 단계는 자동화하지 않는다"

- 에디터에는 이미 사람이 앉아 있고, 3초 들으면 끝나는 판단을 자동화할 이유가 없음. 서버 상시 연산 0.
- 무음 필터는 웨이브폼 생성(어차피 필요)의 부산물이라 추가 비용 0.
- 게임 오디오에도 사람 목소리(더빙·NPC)가 있어 VAD 단독으론 '마이크 트랙' 판별 불가 — 자동 분류의 정확도 함정.
- Whisper 효율·환각 방지는 faster-whisper 내장 vad_filter(Silero)로 해결(무음 스킵 가속).
- 사람이 없는 유일한 플로우(원클릭 자동 업로드)는 템플릿에 자막 트랙 번호를 고정 지정(PID 고정이라 안정) + 렌더 전 RMS 무음 체크로 커버.

## 검토한 대안

- **상시 VAD 파이프라인(인제스트 중 전 트랙 분석)**: 초기 검토안. 서버 상시 연산 발생 + 정확도 함정(게임 내 음성) + 결과를 쓰는 곳이 결국 '사람이 앉아 있는 에디터'라 가치가 없음 → 탈락.
