# ADR-018: 스트림 키 저장 분리 — streamid 해시(PG) / passphrase 원문(Secrets Manager)

- **상태**: 제안 (팀 리뷰 후 채택 — M1 "SRT 입력 규약" 계약과 함께 확정)
- **결정일**: 2026-07-23
- **관련**: [ADR-001](ADR-001_송출프로토콜.md) · [ADR-006](ADR-006_DB_PostgreSQL.md) · [ADR-012](ADR-012_계정권한.md) · [ADR-013](ADR-013_인프라.md)
- **반영 산출물**: 10_데이터플로우 · 11_역할분담(계약4) · 9_기능명세서 · 5_CA

## 컨텍스트

10_데이터플로우의 PG 스키마는 스트림 키를 `stream_keys (id, user_id, key_hash, active, created_at)` 한 테이블에 **해시 하나(`key_hash`)** 로 담는다. 그러나 스트림 키는 **성격이 다른 두 값의 묶음**이다:

- **streamid** — SRT 핸드셰이크에서 스트림을 식별하는 문자열. 서버는 "유효한가"만 **대조**하면 된다.
- **passphrase** — SRT 연결 자체를 암호화(AES)하는 **열쇠**. 서버가 암호화 세션을 성립시키려면 **원문 값이 필요**하다.

단방향 해시는 원문 복구가 불가능하므로 `key_hash`만으로는 passphrase를 SRT에 공급할 수 없다. 즉 **현 스키마는 streamid엔 맞지만 passphrase엔 기술적으로 성립하지 않는다.** 한편 passphrase 원문을 PG 평문으로 두면 DB 유출 시 전 스트리머의 송출 경로가 열린다(5_CA 보안 원칙 "비밀은 코드·DB 밖"과 충돌).

## 결정

스트림 키를 **두 값으로 분리하여 저장 위치를 다르게** 한다.

| 값 | 필요한 연산 | 저장 위치 | 형태 |
|---|---|---|---|
| **streamid** | 대조(검증)만 | **PostgreSQL** `stream_keys` | **해시**(`streamid_hash`) |
| **passphrase** | **원문 공급**(암호화 열쇠) | **Secrets Manager** | 암호화 보관, PG엔 **참조만** |

- PG 스키마를 `stream_keys (id, user_id, streamid_hash, passphrase_ref, active, created_at)` 로 조정한다. `passphrase_ref`는 Secrets Manager 참조이며 **원문은 절대 PG에 두지 않는다.**
- passphrase를 굳이 PG에 두려면 **KMS 봉투 암호화(envelope encryption)된 값**만 허용한다. **평문 저장·해시 단독은 금지.**
- **검증 흐름**(계약4 "발급=Auth / 검증=Media" 유지): Media가 핸드셰이크에서 streamid를 읽어 → 해당 스트리머의 passphrase를 Secrets Manager(또는 캐시)에서 조회해 연결에 적용 → **암호화 성립 여부가 1차 관문**, **streamid 해시 대조가 2차 관문**.

## 근거

- **암호학적 요구가 다르다** — 검증만 필요한 값은 해시(단방향)가 더 안전하고 충분하다. 반면 암호화 열쇠는 복구 가능해야 하므로 해시로 대체 불가. 하나의 `key_hash`로 뭉뚱그리면 둘 중 하나는 반드시 틀린다.
- **유출 피해 최소화** — passphrase 원문이 DB 덤프에 섞이지 않게 분리한다. **유튜브 토큰 원문을 Secrets Manager로 뺀 것과 동일 원칙**(10_데이터플로우).
- **일관성** — 5_CA 보안 계층(Secrets Manager·KMS)과 정렬되고, IAM 최소 권한으로 "누가 이 비밀을 읽을 수 있나"를 통제할 수 있다.

## 검토한 대안

- **현행 `key_hash` 단일 유지**: 구현은 단순하나 passphrase를 SRT에 공급할 수 없어 **기술적으로 성립하지 않음**. 기각.
- **passphrase까지 PG 평문 저장**: 구현 최단이나 DB 유출 시 전 스트리머 송출 경로가 열림. 기각.
- **전 스트리머 공용 passphrase 1개**: 조회 문제가 사라져 단순하나 한 명 유출 시 전체 무력화·개별 폐기 불가. 기각. (MVP 임시방편으로 쓸 경우 **기한과 교체 계획을 반드시 함께 못박을 것**)
- **PG + KMS 봉투 암호화**: 성립하는 대안. Secrets Manager 대비 로테이션·감사 기능은 약하나 조회 지연이 낮을 수 있어 성능 요구 시 재검토 여지 있음.
