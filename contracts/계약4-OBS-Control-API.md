# 계약4 — OBS Control API (Plugin ↔ Media · Clip · Auth)

> For future Claude: PokeClip **인터페이스 계약4**(11-역할분담 계약 9종 중 하나). 세 갈래(4A·4B·4C)로 이뤄지며 방향과 승인권이 갈래마다 다르다. 이 문서는 2026-08-16 **초안 발행** — 그동안 11_역할분담 표 한 줄 + ADR들로 흩어져 있던 내용을 계약 문서로 승격한 것이다. 근거 정본: [11_역할분담](../11_Pokeclip_역할분담.md) 계약 표 4행 · [ADR-018](../adr/ADR-018_스트림키저장.md) · [ADR-019](../adr/ADR-019_스트림키형식전달.md) · ADR-033(계약4C 승인권 3번 이관, 2026-08-04 — 볼트 decisions, repo adr/ 미발행). 세부 스펙이 (미정)인 항목은 지어내지 않고 그대로 남겼다.

## 0. 공통 규약

- 방송별 **`streamId` 공통 사용** — 세 갈래 모두 같은 방송 좌표를 쓴다.
- 인증: **Bearer stream key** (4A·4B — 플러그인이 제시). 4C는 내부 호출이라 별도(아래).
- 스트림 키의 형식·발급·전달 규약은 [ADR-019](../adr/ADR-019_스트림키형식전달.md)가 정본: streamid `#!::r=<26자 Crockford Base32>,m=publish` / passphrase 32자(AES-256) / 방송 중 재발급 차단(MVP) / 자격증명 전달 = 페어링 코드.
- 저장 분리는 [ADR-018](../adr/ADR-018_스트림키저장.md)가 정본 — **단 ADR-018의 상태는 "제안"이다**(팀 리뷰 후 채택, M1 "SRT 입력 규약" 계약과 함께 확정 예정): streamid는 해시로 PG(대조용), passphrase는 원문으로 Secrets Manager(Media가 직접 조회 — 진행 중 라이브는 Auth 상태와 분리). 채택 확정 시 이 표기를 갱신한다.

## 1. 갈래별 정의·구현 상태 (ADR-033 표 기준)

| 갈래 | 방향 | 엔드포인트 | 핵심 규칙 | 구현 상태(2026-08-04 기준) |
|---|---|---|---|---|
| **4A** 트랙 매니페스트 | Plugin(1) → Media(1) | `PUT /api/streams/{streamId}/track-manifest` | `manifestVersion` 멱등·단조 증가 | 양쪽 미착수 |
| **4B** 핫키 마킹 | Plugin(1) → Clip(3) | `POST /api/streams/{streamId}/marks` | `Idempotency-Key=eventId` · 2A와 동일한 `broadcast.started`=0 방송 좌표 | 양쪽 미착수 |
| **4C** 스트림키 검증 | Media(1)·Clip(3) → Auth(3) | `POST /internal/stream-keys/resolve` | 아래 2절 | **Auth 구현 완료**, Media 수신부 미착수 |

- 4A·4B의 요청 본문·재시도·오프라인 큐 등 상세 스펙은 **(미정)** — 플러그인 착수 시점에 재검토·확정한다(ADR-033 결정 4). 표에 있는 것 이상을 이 문서가 앞서 확정하지 않는다.

## 2. 4C 스트림키 검증 (resolve) — 상세

- **엔드포인트: `POST /internal/stream-keys/resolve`.** 구 표기 `verify`는 ADR-033 결정 3으로 `resolve`가 확정되며 대체됐다(3번의 기구현 정본을 인정 — 이후 이 갈래는 3번 단독 결정 사항).
- **인증: `X-Internal-Token` 헤더** (내부 서비스 간 호출).
- **키가 틀려도 HTTP 200 + `valid:false`로 응답한다.** 이유: Media에게 "키 틀림"(그 송출을 거절)과 "Auth 장애"(판단 불가)는 조치가 정반대인데, 둘 다 4xx면 구분이 안 된다. 4xx/5xx는 곧 "Auth 쪽 문제"라는 신호가 된다.
- 요청·응답 본문의 전체 필드 스키마: **(미정 — Auth 구현이 사실상 정본이며, Media 수신부 착수 시 이 문서에 확정 기입)**.

## 3. 승인권 (ADR-033, 2026-08-04)

- **4A·4B 계약 승인 = 1번** (보내는 쪽이 플러그인=1번 소유, 4A는 받는 쪽도 1번).
- **4C 계약 승인 = 3번** (구현·운영이 3번 — 문구 승인만 1번을 거치던 왕복 제거). 규약 변경 시 1번 통지는 존속.
