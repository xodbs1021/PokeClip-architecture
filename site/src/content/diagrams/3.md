> 원본 SA(애플리케이션 아키텍처) 다이어그램을 반응형 문서로 재구성한 뷰. 화면 ↔ 서비스 6종 ↔ 데이터 매핑 · EDGE 스타일 모노크롬 — 역할 그룹(Client·Service·Queue·Worker·Cache·Database·Storage)과 환경 컨테이너로 구획, 배선은 단일 스타일 직교 엘보(동기/비동기 구분 없음), 상세 기능은 아래 본문.

**이 문서의 위치**: IA(화면 트리)와 SysA(서비스·배포) 사이의 화면↔서비스↔데이터 매핑. 서비스 분해와 언어(Spring·Go·Node·Python)는 팀 3인(FE1·BE2) 확정 스택. 클립 렌더는 FFmpeg 프로세스 호출이므로 Spring 잡 워커에 편입.

## 화면 (클라이언트)

- **OBS 플러그인**: SRT+TS 동시 송출(영상+오디오 6트랙) · 오디오 소스 탐지·트랙 매핑 · 핫키 마킹 · 자동 재연결·송출 통계
- **온보딩·설정**: 구글 로그인·유튜브 연동 · 채널 등록(치지직·SOOP) · 편집자 초대·권한 토글 · 템플릿 관리
- **라이브 뷰**: DVR 플레이어(저지연+1h) · 점프카드 스트립(실시간) · 채팅량 차트 · 송출 상태 위젯
- **클립 에디터·보관함**: 구간·비율·오디오 트랙 선택 · AI 자막·추천 제목 · 저장(레시피)·재편집 · 승인 대기함·업로드 결과
- **VOD 뷰 (60일)**: VOD 재생·챕터 탐색 · 오디오 트랙 전환 · VOD에서 클립 제작
- **운영 콘솔 (운영자)**: 계정 관리·사용 통계 · 시스템 모니터링·장애 대응

## 서비스 6종

각 서비스 박스의 기능 ID 그룹은 11번(역할분담)이 9번(기능명세)에 배정한 오너십을 그대로 옮긴 것이다.

### Auth·Account Service — Java · Spring Boot · `H1~H5`

구글 OAuth 로그인·JWT · 편집자 초대·권한(업로드/자동업로드) · 채널 등록·유튜브 토큰 보관 · 스트림 키 발급·검증

### Clip Service — Java · Spring Boot · `D2·E2·E3·E8·F4`

점프카드 생성·SSE 푸시(핫키·자동) · 레시피 CRUD·템플릿 · 웨이브폼·무음 필터(구간 디코드) · 승인 플로우·클립 상태 관리 · **워커 잡 상태·AI 결과를 API로 받아 영속화**(계약1·8)

### Media Origin ⭐ — Go (직접 구현 · MediaMTX 참조) · `B1~B7`

SRT 수신(streamid·암호)·TS 디먹스 · CMAF 세그먼트·LL-HLS 서빙(DVR 1h) · 멀티오디오 rendition·세그먼트 S3 적재 · VOD 매니페스트 확정·**방송 생명주기 이벤트만 발행**(잡 생성은 Clip 전담)

### Chat Collector·Analytics — TypeScript · Node (기존 자산 리팩토링) · `C1~C6`

치지직(공식/비공식)·SOOP 수집 · 플랫폼별 시차 보정→타임라인 정렬 · 채팅 차트 집계(윈도우·참여율) · 하이라이트 탐지→점프카드 요청

### Render·Upload Worker — Java · Spring (FFmpeg 프로세스 지휘) · `F1~F5`

클립 렌더(비율 5종·번인·amix·-14 LUFS) · 유튜브 resumable 업로드·CC 등록 · 쿼터 관리·재시도 · **잡 상태·업로드 결과는 DB 직접 쓰기 없이 Clip Service로 보고**(계약1)

### AI Worker — Python (faster-whisper) · `E4·E7`

선택 트랙 자막 생성(vad_filter) · 자막 기반 추천 제목 · **결과는 Clip Service API 경유로만 반영**(계약8 — DB 직접 쓰기 금지)

## 데이터 계층

메타데이터·상태·포인터만 PostgreSQL, 미디어 바이너리는 전부 S3(ADR-005). PG 안에서도 테이블은 **소유 서비스가 나뉘며, 워커는 PG에 직접 쓰지 않는다** — 다이어그램의 PG 실린더 주석은 이 소유를 표시할 뿐 직접 쓰기 엣지가 아니다(소유는 논리적, 쓰기 경로는 워커→Clip Service→PG).

- **PostgreSQL** (테이블 소유, 10번 §3·§4):
  - `Auth` — users · channels · editor_grants · stream_keys
  - `Clip` — broadcasts · jump_cards · recipes · clips · templates · jobs
  - `Chat` — chat_metrics (윈도우 단위 집계만 · 채팅 원문은 S3 아카이브)
- **Redis**: 세션 · 라이브 상태 · 채팅 집계 캐시 · SSE 팬아웃(pub/sub)
- **S3**: 세그먼트 한 벌(핫 1h 롤링·콜드 전체) · VOD(60일) · 클립(영구) · 채팅 아카이브

## 잡·이벤트 큐 — 4종 (SQS / Redis Streams · 10번 §2)

큐는 "맡기는 주체"가 아니라 생산자와 소비자 사이의 버퍼다. 종류별 생산자·소비자가 다르다.

| 큐 | 생산자 | 소비자 | 하는 일 |
|---|---|---|---|
| **방송이벤트** | Media Origin | Chat Collector · Clip Service (**2소비자 팬아웃**) | 채팅 수집 시작·종료 트리거 / broadcasts 레코드·VOD 확정 |
| **렌더 잡** | Clip Service | Render·Upload Worker | FFmpeg 렌더(구간 컷·크롭·번인·amix·-14 LUFS) |
| **AI 잡** | Clip Service | AI Worker | faster-whisper 자막(vad_filter)→추천 제목 |
| **업로드 잡** | Clip Service | Render·Upload Worker | 유튜브 resumable 업로드·CC 등록·쿼터 관리 |

방송이벤트 1큐가 두 소비자로 팬아웃하는 것이 핵심 — Media는 사실만 알리고, 채팅 수집과 방송 레코드 생성이 각각 독립적으로 반응한다.

## 인터페이스 계약 8종 — 엣지 라벨 (11번)

다이어그램의 연결선 라벨은 서비스 경계에서 만나는 인터페이스 계약이다.

| # | 계약 | 다이어그램 엣지 |
|---|---|---|
| 1 | SQS 잡 메시지(렌더·AI·업로드) | Clip→렌더/AI/업로드 큐 · **워커→Clip 잡 상태·업로드 결과 보고** |
| 2 | 점프카드 SSE + 채팅 차트 API | 라이브 뷰→Clip / 라이브 뷰→Chat |
| 3 | LL-HLS/DVR 재생 URL·매니페스트 | 라이브 뷰→Media · VOD 뷰→Media |
| 4 | 스트림 키(발급=Auth·검증=Media) | OBS 플러그인→Auth(발급) |
| 5 | 유튜브 토큰(보관=Auth·사용=업로드 워커) | Render 워커→YouTube(계약5 토큰) |
| 6 | 레시피 JSON(crop·트랙·자막) — **최우선 확정** | 클립 에디터→Clip |
| 8 | AI 결과 반영 API(워커→Clip, DB 직접 쓰기 금지) | AI Worker→Clip |

> 계약7(FFmpeg 구간 디코드 커맨드 스펙, 1→3)은 런타임 엣지가 아니라 Clip Service의 웨이브폼·무음 필터(E2·E3) 구현에 1번이 제공하는 스펙이라 연결선이 아닌 서비스 기능으로 표현된다.

**불변식 재배선 메모**: 워커(Render·AI)는 PostgreSQL에 직접 쓰지 않는다. 잡 상태·업로드 결과는 워커가 Clip Service로 보고(계약1)해 Clip이 영속화하고, AI 결과도 계약8 API로만 반영된다 — 스키마 오너(3번)의 통제 밖에서 상태가 변하지 않게 하기 위함.
